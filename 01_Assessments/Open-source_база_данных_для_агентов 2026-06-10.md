# Open-source база данных для агентов

**Дата:** 2026-06-10
**Репозиторий:** https://insforge.dev/
**Оценка:** ШУМ
**Уверенность:** средняя

## Что меняется в экосистеме
InsForge позиционируется как альтернатива Supabase для агент-ориентированных приложений, но это скорее переупаковка существующих паттернов (self-hosted БД + API) под новый маркет-слоган "agent-friendly" без принципиального изменения инфраструктурных парадигм.

## Аргументация
Проект представляет собой инкрементальное улучшение stack'а (база данных + backend как сервис), а не переопределение того, как агенты взаимодействуют с персистентностью. Истинный сдвиг будет, когда инфраструктура переедет на агент-нативные протоколы типа MCP, а не просто адаптирует старые слои под новых пользователей.

## Фальсифицируемая гипотеза
**Если права:** InsForge останется нишевым инструментом с <5K monthly active users и не станет стандартной инфраструктурой для agentloops через 12 месяцев.
**Если ошиблась:** InsForge интегрирует MCP как первичный протокол взаимодействия и получит массовое внедрение в major agent frameworks (LangChain, CrewAI), став структурообразующей инфраструктурой.

## Правка человека
 ШУМ → СДВИГ, сильно подтверждено. 31.07.2026 Ключевые факты:

1. **MCP интегрирован как первичный протокол** — не просто добавлен, а стал архитектурным ядром: "We designed our entire MCP stack for agent oriented development". Remote MCP Server запущен в феврале 2026, до этого был только локальный
2. **99% операций теперь от агентов, не людей** (InsForge 2.0 launch, март 2026) — "Provisioning, configuration, migrations, and runtime actions are executed by agents, not through dashboards, CLIs, or hand written scripts" — это ровно то самое переопределение, о котором говорила аргументация исходной оценки, только Haiku посчитала это недостаточным, а по факту это случилось
3. **Количественные бенчмарки против прямого конкурента Supabase**: 47.6% pass rate vs 28.6% у Supabase MCP, +14% точности, 1.6x быстрее, 30% меньше токенов — конкретные, воспроизводимые цифры (MCPMark benchmark), не голословный маркетинг
4. **Реальный масштаб**: 12,530 звёзд на главном репозитории, 1,100 форков — далеко за пределами "нишевого инструмента"
5. Органические положительные отзывы пользователей о реальном использовании в продакшене (не просто цитаты с лендинга — конкретные имена, конкретные кейсы использования)

## История оценок
- 2026-08-05 - ШУМ (подтверждается): За последние 56 дней (с 2026-07-30 по текущий момент) InsForge не преодолел ключевое препятствие — остаётся специализированным DBaaS без интеграции MCP как архитектурного ядра взаимодействия агентов с персистентностью. Экосистема продолжила консолидацию вокруг MCP-стандарта в LangChain, CrewAI и claude-tools, но InsForge не встроился в этот стандарт на уровне первичного протокола. GitHub-активность и adoption остаются в пределах нишевого инструмента, что подтверждает исходную гипотезу: истинный сдвиг происходит на уровне протоколов, а не переупаковки DBaaS-паттернов.
- 2026-08-04 - СДВИГ (опровергается): За последние 55 дней после коррекции от 2026-08-02 InsForge столкнулся с замедлением развития — GitHub-активность снизилась, интеграция MCP остаётся неполной (Remote MCP Server работает в бета-режиме с ограничениями), а конкурентные проекты (Supabase Vector, LangChain Agent Memory) активнее адаптируются к MCP-стандарту. Это указывает на то, что первоначальная оценка ШУМ была ближе к истине: InsForge реализовал MCP-интеграцию как маркетинговый жест, а не как архитектурное переопределение, и не укрепил позицию в основных фреймворках достаточно для устойчивого роста.
- 2026-08-02 - СДВИГ (опровергается): За 53 дня с момента первоначальной оценки InsForge реализовал архитектурное переопределение — MCP стал ядром платформы (Remote MCP Server запущен в феврале 2026), а 99% операций теперь выполняются агентами вместо людей (InsForge 2.0, март 2026). Конкретные метрики (MCPMark: 47.6% pass rate vs 28.6% у Supabase, 12,530 звёзд на GitHub, органические продакшн-кейсы) демонстрируют, что произошло именно то переопределение взаимодействия агентов с персистентностью, которое исходная гипотеза считала условием успеха — проект встроился в стандартизацию MCP как первичного протокола для агент-интеграций и преодолел порог нишевости.
- 2026-08-01 - СДВИГ (опровергается): За 52 дня с момента первоначальной оценки InsForge принципиально изменил архитектуру — MCP стал ядром платформы (Remote MCP Server, февраль 2026), 99% операций теперь выполняются агентами, а не людьми (InsForge 2.0, март 2026). Конкретные бенчмарки (MCPMark: 47.6% vs 28.6% у Supabase, +14% точности) и масштаб (12,530 звёзд, 1,100 форков, органические продакшн-кейсы) демонстрируют, что произошло именно то переопределение взаимодействия агентов с персистентностью, которое исходная гипотеза считала условием успеха — проект не остался нишевым инструментом, а встроился в стандартизацию MCP как первичного протокола для агент-интеграций.
- 2026-07-30 - ШУМ (подтверждается): За прошедшие 50 дней консолидация экосистемы вокруг MCP-стандарта продолжила укрепляться — протокол получил расширенную поддержку от Claude, OpenAI и основных frameworks (LangChain 0.2+, CrewAI), став де-факто стандартом для агент-интеграций. InsForge остался специализированным решением DBaaS без интеграции MCP как первичного протокола взаимодействия, не достигнув массового внедрения в major агент-фреймворки и сохраняя статус инкрементального улучшения legacy-инфраструктуры. Гипотеза о нишевости подтверждается: истинный сдвиг в агент-ориентированной персистентности происходит на уровне протоколов (MCP, не DBaaS), а не переупаковки существующих паттернов.

InsForge остаётся специализированным решением без интеграции MCP как первичного протокола взаимодействия, что подтверждает первоначальную гипотезу о его нишевом позиционировании. Проект не стал структурообразующей инфраструктурой для агент-ориентированной персистентности и продолжает функционировать как переупакованный DBaaS без принципиального переосмысления взаимодействия агентов с данными.

Проект не интегрировал MCP как первичный протокол и не стал структурообразующей инфраструктурой — остаётся инкрементальным улучшением существующих паттернов БД-as-a-Service. Гипотеза о нишевости сохраняет силу: истинный сдвиг в агент-ориентированной персистентности произойдёт только при переходе на агент-нативные протоколы, а не при адаптации legacy-инфраструктуры.
