## Модель — единый источник (99_System/model_config.json)

```json
{
  "haiku": "claude-haiku-4-5-20251001",
  "sonnet": "claude-sonnet-5",
  "updated": "2026-07-04"
}
```

**Правило: model ID никогда не хардкодить в скриптах.** Все вызовы читают из конфига:
```python
MODEL_CONFIG = load_model_config()  # patterns.py, telegram_post.py
model=MODEL_CONFIG["sonnet"]
```
При смене модели правится один файл, не 3 места в 2 скриптах.

### Обязательные параметры для Sonnet 5 в программных (не диалоговых) вызовах:
```python
client.messages.create(
    model=MODEL_CONFIG["sonnet"],
    thinking={"type": "disabled"},   # см. Правило 13
    max_tokens=...,
    messages=[...],
)
```
Не задавать `temperature`/`top_p`/`top_k` — Sonnet 5 возвращает 400 при не-дефолтных значениях.

### Детекция обновлений модели (check_model_updates.py)

Проверяет `platform.claude.com/docs` на новый Sonnet ID каждую пятницу. При расхождении:
- **НЕ меняет** `model_config.json` автоматически (Non-Goal, осознанно)
- Создаёт Feedback в `98_Feedback/Infrastructure/` (структура по `SDD_Feedback_and_System_Evolution_Layer.docx`)
- Шлёт уведомление владельцу в Telegram
- `smoke_test(model_id)` — доступен для ручного вызова, не встроен в автопрогон (не тратить токены зря каждую пятницу)

Обновление `model_config.json` — **только вручную**, после smoke-теста и проверки breaking changes в "What's new" на platform.claude.com. Согласовано с принципом Feedback-Driven Evolution: архитектура не меняется без наблюдаемой причины и решения человека.

## Механика паттернов (patterns.py)

### Три операции за один запуск:

**1. Архивирование** — паттерн не получал новых оценок 90+ дней → статус АРХИВ, файл переезжает в `03_Archive/`.

**2. Фальсификация** — паттерну исполнилось 6 месяцев:
- Sonnet смотрит на новые оценки после даты создания паттерна
- Вердикт: ПОДТВЕРЖДЁН / ОПРОВЕРГНУТ / РАНО_СУДИТЬ
- ОПРОВЕРГНУТ → автоматически в `03_Archive/`
- Промпт явно запрещает использовать знания из обучения — только переданные файлы
- **[ГИПОТЕЗА]** `thinking=disabled` устраняет риск обрезки вердикта при `max_tokens=500`. Не проверено на реальных данных — первые паттерны созданы 2026-06-14, горизонт проверки 2026-12-14 (6 месяцев)

**3. Кластеризация** — группировка новых СДВИГ оценок, минимум 2 оценки на кластер, дедуп по файлам не по названию. С 2026-07-17: в промпт передаются только оценки за последние 14 дней (batch) и только активные паттерны с сигналами за последние 60 дней — ограничивает рост контекста при накоплении vault (см. CHANGELOG v1.11).

### Формат файла паттерна (`02_Patterns/`):

```markdown
# Название паттерна

**Первый сигнал:** YYYY-MM-DD
**Подтверждающие оценки:** [[оценка1]], [[оценка2]]
**Создан:** YYYY-MM-DD (автоматически, patterns.py)
**Статус:** АКТИВНЫЙ

## Суть
[Одно предложение — что меняется структурно]

## Почему важно сейчас
[Добавить вручную]

## Если права / Если ошиблась
[Что увидим через 12 месяцев]

## История наблюдений
- YYYY-MM-DD — паттерн выделен автоматически из N оценок

## Правка человека
<!-- Не согласна с кластером? Добавь строку: - [дата] - [комментарий] -->

## Связи
- [[оценка1]]

**Модель:** claude-sonnet-5
**Промпт версия:** v1.0
```
Блок Модель/Промпт версия — только в `02_Patterns/`. В `telegram_post.py` НЕ добавлять (осознанное решение — метаданные не для аудитории канала).

### Статусы: `АКТИВНЫЙ` / `АРХИВ` / `ПОДТВЕРЖДЁН` / `ОПРОВЕРГНУТ`

## КРИТИЧЕСКИ ВАЖНО — правила которые нарушались

### Правило 1: Всегда проверять реальный путь перед записью
```bash

```

### Правило 2: Помечать гипотезы тегом [ГИПОТЕЗА], проверенные факты — ФАКТ

### Правило 3: Весь вывод только на русском языке
Промпты к Claude — на английском с `Respond in Russian language only`. Шаблоны vault — на русском.

### Правило 4: Функции Python объявлять ДО блока `if __name__ == "__main__"`

### Правило 5: Не перезаписывать существующие файлы оценок и паттернов
`os.path.exists(filepath)` перед любой записью.

### Правило 6: python3 -m py_compile скрипт.py после каждого изменения до пуша

### Правило 7: Никаких em-dash и en-dash внутри Python-строк — только дефис

### Правило 8: Не ставить Protected на CI переменные если ветки не защищены

### Правило 9: Не выполнять git remote set-url без явного указания в какой папке

### Правило 10: Точечные правки — не переписывать файлы целиком

### Правило 11: Спросить что уже есть перед тем как предлагать создать новое

### Правило 12: max_tokens для кластеризации 20+ файлов — минимум 5200
*(было 4000 на Sonnet 4.6 — токенайзер Sonnet 5 даёт ~+30% токенов на тот же текст)*

### Правило 13: thinking={"type": "disabled"} во всех программных вызовах Sonnet без открытого reasoning
Sonnet 5 включает adaptive thinking по умолчанию — расходует тот же `max_tokens`, что и ответ, непредсказуемым образом. Для bounded-задач (классификация, кластеризация, фиксированный формат поста) reasoning не даёт очевидной пользы. Применено в `cluster_with_sonnet`, `falsify_pattern`, `generate_post`.

### Правило 14: sed на macOS (zsh) — только с явным пустым аргументом `-i ''`
`sed -i 's/.../.../' file` на macOS падает синтаксической ошибкой (BSD sed, не GNU). Верно: `sed -i '' 's/.../.../' file`. Для многострочных вставок — Python-скрипт вместо `sed`, кросс-платформенно. При нескольких вставках в один файл по номеру строки — от большего номера к меньшему, иначе после первой вставки нумерация сдвигается.

### Правило 15: gitlink без .gitmodules — диагностика и фикс
`git status` в `master` показывает `modified: radar (new commits)`, при этом `.gitmodules` не существует → случайный gitlink, не настоящий submodule.
```bash
git ls-files -s | grep 160000   # диагностика
git rm --cached radar           # убрать индексную ссылку, файлы на диске не трогает
echo "radar/" >> .gitignore
```

### Правило 16: .gitlab-ci.yml — файл, не набор терминальных команд
YAML редактируется как содержимое файла (heredoc/Python), никогда не вставляется в терминал построчно — часть строк случайно исполнится как shell-команды (например `git clone` внутри `script:` блока реально запустится).

### Правило 17: Cowork не исполняет код и не имеет коннектора к GitLab
Ограничения Cowork: доступные коннекторы — Asana/Canva/Cloudflare/Figma/GitHub/Google Drive/Jira/Linear/Notion/Sentry/Slack, GitLab отсутствует. `py_compile`, `git commit/push` в `gitlab.com/lyolich777ka/radar` — выполняются вручную через терминал или Claude Code, не через Cowork. Cowork пригоден для: текстовых правок файлов, поиска в документации, формирования diff.

### Правило 18: Асимметрия рисков как критерий для routine-решений о конфигурации
Когда выбор между двумя вариантами не требует полной архитектурной таблицы (не архитектура/стратегия, а конфигурация): сравнивать не "что лучше в среднем", а какой вариант имеет **фиксированный известный минус** против **растущего непредсказуемого риска**. Пример: `thinking=disabled` (Правило 13) — выбран за счёт этого критерия.

### Правило 19: Внешний брейншторм — не falsifiable источник по умолчанию
Диалог с другим ИИ-собеседником, принесённый пользователем, не falsifiable источник, если собеседник ни разу не отверг ни одно предложение. Требует отдельного критического прохода прежде чем переноситься в план — не прямого переноса по календарным слотам или задачам.

### Правило 20: Данные, противоречащие контексту, не считать достоверными без проверки
При интерпретации существующих данных (calendar-событий, конфигов, логов), которые противоречат остальному контексту (напр. выглядят как реальный дедлайн или kill-metric) — не считать их достоверными без прямой проверки с человеком.

## Критерий отбора контента для канала

**Несёт ли это СДВИГ?** Сдвиг = изменение в том как организуется знание или ценность в экосистеме — до того как это стало общим местом.

| Проходит | Не проходит |
|---|---|
| Новый паттерн поведения экосистемы | Новость о продукте |
| Смена адресата знания | Обзор фич релиза |
| Изменение структуры принятия решений | "Интересный инструмент" |
| Сдвиг в том кто/что становится инфраструктурой | Популярная тема недели |
