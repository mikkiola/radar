## КРИТИЧЕСКИ ВАЖНО — правила которые нарушались

### Правило 1: Всегда проверять реальный путь перед записью в файл

**Ошибка которая была:** агент прописал путь `~/radar/01_Assessments` не проверив структуру папок. Obsidian создал vault в `~/radar/radar/` — файлы писались мимо vault.

**Правило:** перед любым `open(filepath)` или `os.makedirs` — сначала выполнить `ls` и убедиться что путь существует и правильный.

```bash
# СНАЧАЛА проверить:
ls ~/radar/
ls ~/radar/radar/
# ПОТОМ прописывать путь в коде
```

### Правило 2: Помечать гипотезы тегом [ГИПОТЕЗА]

**Ошибка которая была:** агент писал "контекст накопился большой" и "фильтр их уберёт" как факты — не имея данных.

**Правило:** всё что агент предполагает но не знает точно — помечать [ГИПОТЕЗА]. Факты без пометки. Гипотезы с пометкой.

### Правило 3: Весь вывод только на русском языке

**Ошибка которая была:** при исправлении кодировки агент перевёл промпты и шаблоны файлов на английский. Владелец русскоязычный — это неприемлемо.

**Правило:** промпты к Claude пишутся на английском (лучше работает), но содержат инструкцию `Respond in Russian language only`. Шаблоны файлов vault — всегда на русском.

### Правило 4: Функции Python объявлять ДО блока `if __name__ == "__main__"`

**Ошибка которая была:** функция `fetch_awesome_lists()` добавилась в конец файла после блока запуска — Python падал с `NameError`.

**Правило:** при добавлении новой функции через `cat >>` — всегда проверять порядок. Функции сверху, запуск снизу. Если сомнение — перезаписать файл целиком через `cat >`.

### Правило 5: Не перезаписывать существующие файлы оценок

**Ошибка которая была:** скрипт перезаписывал файл оценки при повторном запуске — терял правки человека (HITL блок).

**Правило:** в `analyze.py` всегда проверять `os.path.exists(filepath)` перед записью. Если файл существует — пропускать, не перезаписывать.

### Правило 6: Не использовать слово "власть" в критериях фильтра

**Ошибка которая была:** в промпте использовалось "знание, власть или ценность" — из старой цели проекта. После разбора сессии Ольга согласилась что "власть" — лишнее слово. Реально работают два критерия: знание и ценность.

**Правило:** критерий сдвига = изменение в том как организуется **знание или ценность** в экосистеме. Без "власти".

## Новая цель проекта

> Строить измерительный прибор агентного и ИИ-рынка через систематическую оценку opensource-проектов — где каждый проект это точка измерения, граф хранит историю изменений оценок с фальсифицируемыми гипотезами, а канал публикует только те наблюдения которые указывают на изменение структуры экосистемы.

**Центр системы — граф, не канал.**
Telegram — публичный интерфейс исследования.
Claude — инструмент первичного анализа.
Opensource проекты — источник данных.

---

## Критерий отбора контента для канала

**Несёт ли это СДВИГ?**

Сдвиг = изменение в том как организуется знание или ценность в экосистеме — до того как это стало общим местом.

| Проходит | Не проходит |
|---|---|
| Новый паттерн поведения экосистемы | Новость о продукте |
| Смена адресата знания (кто/что читает) | Обзор фич релиза |
| Изменение структуры принятия решений | "Интересный инструмент" |
| Сдвиг в том кто/что становится инфраструктурой | Популярная тема недели |

Если сомнение — НЕ публиковать.

## HITL — Human in the Loop

Ольга — архитектор. Claude — инструмент первичного анализа. Оценка Claude не финальная.

Механика:
1. Claude создаёт файл с оценкой и блоком `## Правка человека`
2. Ольга открывает файл в Obsidian
3. Если не согласна — добавляет строку в блок `## Правка человека`
4. Файл не перезаписывается при повторном запуске скрипта

## Голос канала

Ольга пишет от первого лица. Голос:
- Прямой. Утверждение, не вопрос.
- Без вводных. Сразу суть.
- Без объяснений для широкой аудитории.
- Без CTA и призывов.
- Без эмодзи-маркеров списков.
- Длина: 300–800 знаков.

Структура поста:
```
[Утверждение-сдвиг] — одна строка
[Что именно меняется] — 2-4 предложения конкретно
[Почему важно сейчас] — 1-2 предложения
[Один вывод] — не совет, зафиксированная точка
```

**Метрика качества:** хороший пост через год выглядит как предсказание, не как новость.
